# 실행 모드

입력창 아래 실행 모드에서 선택한다. 선택은 대화별로 저장되며 다음 전송부터 적용된다. 실행 중에는 변경할 수 없고 새 작업은 승인 후 실행으로 시작한다.

| 모드 | 동작 |
| --- | --- |
| 승인 후 실행 | 파일 변경과 명령 실행 전에 승인 요청을 표시한다. |
| 계획 · 읽기 전용 | 자료를 읽고 구현 단계와 검증 방법을 작성한다. Harness의 read-only 권한으로 쓰기를 거부한다. |
| 자동 승인 | 파일 변경과 명령 실행을 개별 승인 없이 수행한다. 작업 폴더 밖 접근도 가능한 전체 접근 권한이다. |
| 자동 에이전트 | 자동 승인 권한으로 모델이 독립 작업을 실제 하위 에이전트에 분담하고 결과를 취합한다. |

자동 에이전트는 모델의 도구 호출로 생성된다. 모든 요청에서 생성을 강제하지 않으며 단순한 요청은 직접 처리할 수 있다. 실제 agent 이벤트의 ID별 대기·실행·완료·실패·중지 상태를 답변에 표시한다. 단일 GPU 요청 슬롯에서는 하위 작업이 순차 실행될 수 있다. 중지는 기존 Harness의 부모 및 하위 에이전트 취소 경로를 사용한다.

`/compact` 같은 명령은 모드 지침을 붙이지 않고 전달한다. 현재 모델 설정, 컨텍스트 한도 및 작업 폴더는 변경하지 않는다. 실행 중인 앱에는 F5로 UI를 새로 불러온다.

검증: 모드 매핑·명령 보존·에이전트 병합 단위 테스트와 격리된 Edge UI의 모드별 요청, 재시작 후 선택 유지, 새 작업 기본값, 상태 카드 갱신을 확인했다. 합성 모델을 사용하는 실제 Harness 회귀 테스트는 로컬 Qwen의 자율 분담 품질 검증과 구분한다.

실제 Harness와 합성 모델에서 계획 모드의 파일·명령 쓰기 거부, 자동 승인의 작업 폴더 안팎 쓰기, 수동 승인·거부 및 읽기를 확인했다. 하위 에이전트 생성·대기·완료, 승인 전달, 부모 중지 시 하위 작업 취소 회귀도 통과했다. 로컬 Qwen이 새 모드에서 자율적으로 분담하는지는 이번 변경에서 실모델 검증하지 않았다.
