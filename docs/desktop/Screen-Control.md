# Windows 화면 제어

이미지 입력 준비와 실제 모델 검증은 [Vision.md](Vision.md)를 참고한다.

앱을 완전히 종료하고 다시 실행하면 오른쪽에 **화면 제어**가 표시된다. **화면 제어 허용**을 누른 다음 **창 목록 · 캡처**에서 창을 선택해 스크린샷 또는 접근성 정보를 확인한다. 채팅에서는 “창 목록을 확인하고 메모장의 내용을 입력해 줘”처럼 대상과 작업을 지정한다.

모델 도구는 `desktop_windows`, `desktop_inspect`, `desktop_screenshot`, `desktop_act`다. 클릭·우클릭·드래그·스크롤·한글 입력·단축키, 창 활성화·이동·크기 변경·최소화·복원을 지원한다. Windows UI Automation을 통해 버튼의 Invoke를 시도할 수 있으며 미지원 컨트롤에는 명확한 오류를 반환한다. 입력은 대상 창을 활성화하고 포커스를 재확인한다. 좌표는 창 바깥 테두리의 왼쪽 위 기준 물리 픽셀이며, 창 이동 좌표만 화면 전체 기준이다.

계획 모드는 조회만 허용하고 조작을 거부한다. 승인 후 실행 모드는 각 조작 전에 기존 승인 카드를 표시한다. 자동 승인·자동 에이전트 모드는 개별 승인 없이 조작한다. 화면 제어 허용은 이 권한 모드와 별도로 적용된다.

**화면 제어 긴급 중지**는 모든 대화의 후속 화면 입력을 차단한다. 다시 허용하기 전까지 유지된다. 기존 대화 중지 버튼도 화면 제어를 차단한다. 이미 전달한 클릭은 되돌리지 않으며, 진행 중인 OS 접근성 요청이 즉시 취소된다는 보장은 없다. 입력 루프는 중지 세대와 포커스를 확인하며 드래그는 종료 시 버튼을 놓는다. Escape를 누르고 있어도 다음 입력을 거부한다.

도구 프로세스들은 Windows 이름 있는 mutex 하나를 공유한다. 다른 에이전트가 사용 중이면 대기열로 쌓지 않고 busy 오류를 반환한다. 중지 후 재허용은 세대 ID를 바꾸므로 이전 실행이 다시 살아나지 않는다. 화면 제어 상태 파일은 앱 데이터의 `agent/desktop-control.json`이며 기본값은 비활성이다.

캡처는 선택한 창이 차지하는 **보이는 화면 영역**이다. 겹친 창이 포함되며 가려진 원래 내용을 복원하지 않는다. 이미지 지원이 켜진 로컬 모델 경로에만 MCP 이미지 결과를 전달한다. 현재 경로가 텍스트 전용이면 접근성 트리로 작업하고, 이미지 픽셀을 보았다고 주장하지 않도록 지침을 제공한다. 별도 PNG 파일을 자동 생성하지 않으며 모델에 전달한 도구 결과는 Harness 대화 기록에 포함될 수 있다.

## 검증 및 한계

- 단위 테스트: 조회·조작 권한 구분, 입력 검증, 중지/재허용 세대 변경.
- 실제 Harness + 합성 모델: MCP 도구 등록, 계획 모드 조작 거부, 수동 승인, 자동 모드의 중지 상태 적용.
- 실제 Windows의 전용 합성 창: 접근성 조회, PNG 캡처, 클릭·스크롤·드래그, 한글 입력, 키 입력, 창 이동·최소화·복원, 중지. Invoke 미지원 컨트롤의 좌표 대체 경로 확인.
- 격리된 Edge: 허용·긴급 중지·창 선택·접근성 조회 UI와 기존 대화 기능 회귀.

로컬 Qwen의 자율 화면 작업 성공률, 관리자 창·UAC 보안 데스크톱, 모든 앱의 접근성 지원은 검증하지 않았다. 관리자 권한 창은 입력이 거부될 수 있다. 이 기능은 사용자의 실제 마우스와 키보드를 공유한다.

소스 준비 후 `stage_workspace.py`와 `stage_screen_control.py`를 실행한다. 실행 중인 서버에는 새 코드를 강제 주입하지 않으므로 앱을 다시 실행해야 한다.
